# aman.study

**Live site: [aman-study.vercel.app](https://aman-study.vercel.app)**

A personal library of expert-level study material — courses and deep dives — researched from primary sources and written to be read. New material is generated by Claude Code skills in this repo; the site picks it up automatically.

## Generating material

Three explicit commands (in `.claude/skills/`), all running on Sonnet at `xhigh` effort:

| Command | What it makes |
|---|---|
| `/study-deepdive <topic>` | 1–6 exhaustive pages on one narrow topic (a chip, an architecture, a library, a practice) |
| `/study-course <field>` | A university-style syllabus: parts → 10–40 modules on a whole field |
| `/study-continue <slug>` | Resumes an interrupted run from its `manifest.json` |

Pipeline: **research** (live web search → `sources.json` / `sources.md` source map with verbatim facts) → **plan** (outline or syllabus) → **checkpoint** (you approve; `--go` skips) → **write** (one `study-writer` agent per module, 4 in parallel, each linted) → **assemble**. Every claim carries a research-paper-style citation; claims that could not be sourced are marked `unverified`, never hidden. No exercises, quizzes or deliverables; every module has a "Where experts disagree" section. Rules and references live in `.claude/study/`.

Output: `<category dir>/<slug>/` containing `manifest.json`, `sources.md`, `sources.json`, `outline.md` | `syllabus.md`, and one self-contained `NN-slug.html` per module (opens directly in a browser, or through the site).

## Structure

```
.
├── .claude/
│   ├── skills/study-{deepdive,course,continue}/SKILL.md   the three commands
│   ├── agents/study-{researcher,planner,writer}.md         Sonnet · xhigh agents
│   └── study/                                             shared library
│       ├── references/   learner profile, content standards, research/course/deep-dive guides,
│       │                 module template, component catalogue, diagram guide, manifest schema
│       └── scripts/      lint-module.mjs · validate-manifest.mjs · manifest.mjs · build-bibliography.mjs
├── computer science/<track>/manifest.json + content        (also finance/, maths/, business/)
├── From_Zero_to_Quant/
└── website/                                               Next.js 16 site
    ├── lib/registry.ts        discovers every manifest.json under the repo root at build time
    ├── app/[track]/…          one dynamic route renders every track, part, module, appendix
    └── public/study/          study.css · study.js · demo.html · vendor (KaTeX, highlight.js)
```

## Tech stack

Next.js 16 (App Router, TypeScript) · Tailwind CSS 4 · KaTeX · highlight.js · react-markdown for the legacy markdown tracks · Vercel.

## Development

```bash
cd website
npm install
npm run dev          # http://localhost:3000 — tracks with status ≠ published are visible here only
npm run build        # prerenders every route from the manifests
```

`website/public/study/demo.html` is the component gallery for HTML modules (also served at `/study/demo.html`); `computer science/study-fixture/` mounts it inside the site in dev.
