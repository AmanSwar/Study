def kv_bytes_per_token(layers, kv_heads, head_dim, dtype_bytes):
    """Bytes of KV cache written per generated token (K and V)."""
    per_layer = 2 * kv_heads * head_dim * dtype_bytes
    total = layers * per_layer
    return total

8. Stepper (step-through diagram)

  1. Producer warp issues a bulk tensor copy from global to shared memory; it costs one thread, not a warp.
  2. Transaction barrier counts bytes landed; consumers wait on the phase bit, not on threads.
  3. MMA warpgroup issues the tensor-core op from one elected thread; accumulators live in TMEM.
  4. Epilogue warpgroup drains TMEM, applies scaling, stores via TMA. Steps 2–4 overlap across stages.

11. Where experts disagree

Mandatory in every module: at least two positions, each cited, then the author's assessment.

Hand-written kernels are the moat

Kernel-centric shops; several ThunderKittens/CUTLASS write-ups3

Library kernels leave 20–40% on the table for real shapes; the residual is only recoverable by owning the kernel.

  • True for skinny GEMMs and fused attention variants
  • Assumes a team that can maintain SM-specific code across generations

Scheduling and placement dominate

Serving-system papers; vLLM/SGLang maintainers1

End-to-end goodput is set by batching policy, prefill/decode split, and expert placement — kernels are near-roofline already.

  • Matches published provider numbers
  • Understates the gap on new hardware before libraries catch up
Assessment

Both are right at different points on the hardware-maturity curve: kernels matter for the first ~9 months of a new SM generation; after that, scheduling dominates. Plan accordingly.

12. Disclosure

Derivation of the batch-size crossover

Set compute time equal to memory time: \( \frac{2 P B}{F} = \frac{P b}{W} \Rightarrow B^\* = \frac{F b}{2 W} \). With \(F = 4.5\) PFLOPS, \(W = 8\) TB/s, \(b = 1\) byte: \( B^\* \approx 281 \).

B_star = (4.5e15 * 1) / (2 * 8e12)   # ≈ 281
